# Canonical Requirements Register

This file is the single canonical requirements register for the documentation baseline.

## Status And Disposition Notes

- `PROPOSED`, `VERIFIED`, `OPEN DECISION`, `IMPLEMENTED`, `PLANNED`, `REJECTED`, `CONTRADICTED`, and `DEPRECATED` are the only allowed status values in this baseline.
- `AS-BUILT FACT`, `CANDIDATE LONG-TERM REQUIREMENT`, `CANDIDATE ARCHITECTURE DECISION`, and `OPEN STAKEHOLDER DECISION` are the only allowed disposition values.
- `DATA` records represent shared API contract surfaces that are already implemented.
- `INT` records represent the evidence and integration-test baseline that is already implemented.
- `OPEN` records represent unresolved stakeholder decisions and remain intentionally non-final.
- `OPEN-03`, `OPEN-04`, and `OPEN-05` use `VERIFIED` for the implemented workforce scope under the [recorded approval](./ACCESS_CONTROL_BASELINE.md#recorded-approval), while their patient-facing limitations remain blocked and explicitly non-final.
- The recorded approval and Sprint 15 implementation permit synthetic-data design, implementation, and testing only; production deployment and processing of real patient data remain blocked by the unresolved decisions and reviews documented in the approval.
